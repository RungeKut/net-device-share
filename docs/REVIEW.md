# Чек-лист код-ревью

Дерево — карта прохода: зашёл в ветку, прошёл листья, отметил. Каждый лист —
с коротким «почему», чаще всего с живым примером из этого проекта: грабля,
на которую уже наступали. Это не общая теория — здесь только то, что здесь
уже стреляло или вот-вот выстрелит.

**Как пользоваться.**
Мелкий diff (до ~50 строк, одна подсистема): ветки 0, 1, 2 и любой раздел,
куда попала правка. Большой diff или новая подсистема: проход по всем веткам.
Ревью с «нечего смотреть» — признак пропущенной ветки, а не чистого кода.

**Как пополнять.** Новый граблистный случай → листик в ближайшую по смыслу
ветку, одной строкой, с «почему» и примером. Подходящей ветки нет → новая
ветка в дереве (и строка в карте ниже), а не «прочее»: прочее не читают.
Уровень вложенности больше трёх — повод разбить ветку. Лист, который ни разу
не стрелял и не защитил за год, — вычеркнуть: чек-лист должен быть коротким.

## 0. Подготовка

- [ ] `git log --oneline` + `git diff --stat`: масштаб и замысел; замысел diff
  формулируется одним предложением — если не формулируется, ревьюить рано.
- [ ] `npm run check` и `npm test` прогнаны (падающий прогон не ревьюят — сперва чинят).
- [ ] STATE.md и HANDOVER прочитаны: сделанное не противоречит зафиксированным
  решениям и списку «не проверено».
- [ ] Разнородные изменения разнесены по коммитам: смешанный коммит ревьюить
  труднее, а откатывать — невозможно.

## 1. Границы доверия

### 1.1 Кто может позвать

- [ ] У каждого нового HTTP-маршрута определён уровень: только локально
  (`X-NDS-UI` на каждом POST) / межузловой (подпись круга) / метрики (токен).
  Пропущенный POST — управление без пароля.
- [ ] Межузловой вызов идёт через `realms.matchRequest` (подпись v2: метод +
  путь + отправитель + время), а не через самодельное сравнение.
- [ ] Открытый круг — осознанное решение «умеет всё, что дотянулось до порта»:
  для каждой новой ветки от него проигран сценарий «чужой из другой подсети
  дотянулся до 47812» (туннели и пересказ каталога построены на этом слое).
- [ ] Право на действие проверяет владелец состояния, а не вызывающий
  (`release`/`renew` — только держатель, `answerRequest` — только держатель).

### 1.2 Подписи и секреты

- [ ] Любое сравнение секрета, токена, подписи — `crypto.timingSafeEqual`
  после проверки длины (подписи, пароль, токен метрик, токен L2-канала).
- [ ] Подпись покрывает всё, от чего зависит решение: тело без пути и
  отправителя позволял повторить вызов от чужого имени (см. подпись v2).
- [ ] Секреты не утекут: журнал, `/api/v1/state`, каталог соседям, метрики,
  файл настроек (только хеш; отпечаток круга — можно, ключ — нет).
- [ ] Окно свежести подписи (10 мин) не обходит новая ветка; nonce — ещё не
  сделан, повтор в окне возможен — новая ветка не должна это ухудшить.

### 1.3 Недоверенные данные

- [ ] Каждый `JSON.parse` из сети — в try/catch; кривой пакет не крашит узел.
- [ ] Поля проверены на тип и диапазон: `typeof`, `Number.isInteger`,
  порты 1–65535, адреса — до использования (мусор из анонса доехал
  до белого списка портов туннеля — чистили фильтром).
- [ ] Всё сетевое слово в UI — `esc()` или `textContent`: имена узлов,
  описания, журналы, адреса (чужой узел не должен исполнять JS в браузере).
- [ ] `href`/`window.open` — только после проверки адреса (`nodeUrl`).
- [ ] Составные идентификаторы занятия в `data-`-атрибутах — через
  `splitLast`, не `split('|')` (деление по всем `|` теряло занятие).

### 1.4 Команды и пути

- [ ] `spawn` только с массивом аргументов, никакого `shell:true`; строки для
  PowerShell — через `psQuote`; в `netsh` попадают только проверенные адреса.
- [ ] Пути из параметров/сети: `path.resolve` + проверка префикса (статика,
  `/download`, распаковка драйверов, tar — везде уже есть).
- [ ] Установщики и драйверы: SHA-256 и подпись/отпечаток проверяются ДО
  запуска с правами администратора.

## 2. Гонки и порядок операций

- [ ] Каждый `await` — окно: что если в это время то же самое делает другой
  узел, таймер или пользователь? Проиграть интерливинг, не «повезёт».
- [ ] Состояние закрывается до первого `await` или меткой «готовится»
  (`preparing`, `busyTaps`, ранний `lends.set`): третий узел в окне между
  удалением занятия и концом unbind забирал устройство.
- [ ] Флаг занятости ставится синхронно до первого `await` (updater.busy —
  тик таймера и «Обновить сейчас» качали одну версию дважды).
- [ ] Удаление записи после долгой операции — по идентичности, не по ключу
  (`attachments.get(id) === rec`: повторное занятие во время detach
  затиралось старым detach).
- [ ] Бронь/hold ставится ДО освобождения, а не после (окно release длиной
  в секунды unbind забирало цель у просителя).
- [ ] Перезапуск подсистемы (`stop()` + `start()`) не плодит параллельные
  цепочки таймеров — одного флага `stopped` недостаточно, нужен счётчик
  поколений (directory, `_syncLegs` сериализована).
- [ ] `setTimeout`/`setInterval` из длинных цепочек (`.finally(() =>
  schedule())`) не воскресают после `stop()`; у таймеров `unref`.

## 3. Сбои ≠ пустота

- [ ] Сбой опроса неотличим от «списка пуст»? Пустой список отзывал все
  аренды при одном сорванном PowerShell — сбои оставляют прошлый результат
  (`_lastUsb`, `_slow`).
- [ ] При ожидании исчезновения сбой чтения — «неизвестно», а не «исчезло»
  (`waitTaps`: ложное «удалён» навсегда терял живой адаптер).
- [ ] «Успех» команды PowerShell проверен по факту, а не по отсутствию ошибки:
  `psJson` без `strict` на сбое молча отдаёт `[]`, и «чистка ARP прошла»
  означала «команда не запустилась». Список состояний соседей с несуществующим
  `Deep` ронял `Remove-NetNeighbor` при разборе аргументов целиком — чистка не
  делала ничего несколько версий подряд. Для перечислений Windows (`-State`,
  `-AddressFamily`) — только имена из самого перечисления (проверить в консоли),
  а фильтр по состоянию — в конвейере; после записи (`New-NetNeighbor`) читать
  обратно.
- [ ] Ошибка на пути данных управляема: `sink.destroy` на голом EventEmitter
  давал TypeError вместо остановки релея.
- [ ] Многошаговая операция переживает частичный отказ: откат сделанного +
  пометка в config (`netLent`) + дочистка при следующем заходе
  (`_ensureBridgeFree`).
- [ ] Все fire-and-forget вызовы с `.catch`; `unhandledRejection` не оставляет
  состояние в середине шага.
- [ ] Ошибка одного соседа не тянет за собой остальных (heartbeat был
  последовательным — один мёртвый владелец срывал аренды живых).

## 4. Ресурсы и утечки

- [ ] Сокеты: обе стороны `destroy()` при ошибках и закрытии; переподключение
  закрывает прежний сокет.
- [ ] Растущие Map: MAC-таблица (предел 4096 с вытеснением), `tunnelCache`
  (срок + чистка при забвении шлюза), `directory.pulled`.
- [ ] Дочерние процессы: таймаут, kill, кодировка вывода; PowerShell-очереди
  не множат параллельные запуски (`_slowInFlight`).
- [ ] `stop()` гасит всё: таймеры, сокеты, reaper, graceTimer (нашёлся один
  вне реестра таймеров).
- [ ] В тестах — `listen(0)` и tmp-каталоги; фиксированный порт — только с
  комментарием-оправданием.

## 5. Windows-специфика

- [ ] Кодировки: bat — CP866 + CRLF (не трогать руками, проверит
  `check-files`); ps1 — UTF-8 с BOM; вывод `cscript` — cp866; успех netsh —
  по коду выхода, не по тексту; маркеры (`NDS-RESULT`) — латиницей.
- [ ] Фильтры «настоящая сеть» не режут законные случаи: прямой кабель между
  двумя ПК бывает на любой подсети (200.100.1.0/24), а не только на частной;
  автоадрес 169.254 — единственное, что отсекается по адресу. Проверять на
  реальном списке адаптеров машины, а не на «типичном» (`resolveNetworks` с
  `nets` в тесте).
- [ ] Локализуемые строки не парсятся: «Multiplexor|MAC Bridge» зависит от
  языка Windows — надёжнее `ComponentID ms_implat`.
- [ ] Сети с одинаковыми адресами (офис /21 и сеть стенда /24 с теми же адресами):
  маршрут, выбранный Windows, и запись о соседе на другой карте решают, куда уйдёт
  пакет; приложение должно проверять выбор (`routeChoice`), а не надеяться на
  «более узкую маску».
- [ ] Кавычки и пробелы в путях и именах (psQuote; Compress-Archive с
  одинарными кавычками ломался на апострофе).
- [ ] Права администратора: новая ветка работает без них или честно
  сообщает, что не так (полусделанная работа без прав хуже отказа).
- [ ] `.gitattributes`: подписанные и двоичные файлы — `-text` (INF с LF
  рвал подпись `.cat` на свежем клоне), `eol` для bat/ps1/sh.
- [ ] Возврат системы в прежнее состояние: настройки IP, автозапуск, мост —
  что вернётся при сбое и при остановке приложения.

## 6. Протокол и совместимость версий

- [ ] Новое поле в пакетах/ответах только добавляется; старый узел не должен
  отвалиться (`protoCompatible`, самообновление едет по этой же сети).
- [ ] `stateHash`: новое состояние меняет хеш, если соседи должны узнать
  об изменении; меняющиеся каждую секунду байты — нет (в хеш — признак
  активности, не цифры).
- [ ] Обратная совместимость с оговоркой: старая подпись принимается до
  `strictSignatures` — новая ветка не делает старую подпись обязательной.
- [ ] Круги доверия не смешиваются: пересказ и приём каталога фильтруют по
  `realm`; новый путь (шлюз, туннель, seed) не должен стать мостом между
  чужими кругами.
- [ ] Ретрансляция каталога не зацикливается (`relay` не пересказывается),
  запись чужого узла не перезаписывается без нужды.

## 7. Интерфейс

- [ ] Сетевые строки — `esc()`/`textContent` (см. 1.3); `innerHTML` — только
  собранный из экранированных кусков.
- [ ] Необратимые действия — с подтверждением (`confirm` или `<dialog>`);
  диалог объявлен в index.html, обработчик `close` различает «отмена» и ответ.
- [ ] Кнопки `disabled` на время действия (`action()`), состояние «пусто» и
  «ошибка» показаны, а не молчание.
- [ ] Занятость и скорость: новая сущность видна в каталоге так же, как
  занятие (плашка, скорость, «кто и как давно») — мост однажды остался без
  скоростей, метрики тоже (см. 8).
- [ ] Каждое «занято/активно» в коде — по всем видам занятости, не только по
  `claim`: у карты в общем мосту `claim` нет, держатели лежат в `joins`.
  `PeerRegistry._refreshBusy` проверял одно `claim`, мост у соседей не
  опрашивался, и скорость клиентов моста замерзала (обычное занятие при этом
  работало — потому и не заметили). Тест гонять для каждого вида занятости.
- [ ] Время, которое идёт само (обратный отсчёт, «N с назад»), — метка
  времени в снимке и пересчёт в окне по таймеру, а не готовая строка с
  числом: серверное `message` собрано один раз и стоит, пока не придёт новое
  состояние (подтверждение новой версии «через 45 с» не тикало). Число в
  строке — повод заподозрить застывший счётчик.
- [ ] Таймер интерфейса не пересоздаёт DOM с кнопками: перерисовка раз в секунду
  между нажатием и отпусканием теряет клик («Обновить сейчас»). Тик меняет
  `textContent` помеченных узлов (`data-live`), а не `innerHTML` полосы.
- [ ] Признак «сам» считается тем же кодом, что и для соседей: запись о себе в
  каталоге строится отдельно (`owners[0]` в `app.js`) и не получала поле `nets` —
  метка «шлюз» у себя не рисовалась. Новое поле узла — в обе ветки сборки.
- [ ] «Есть две сети» ≠ «шлюз»: признак считается по живым соседям в каждой
  сети, а не по числу поднятых карт (карта на коммутаторе остаётся Up, когда
  кабель оборван на другом конце). Любой признак узла, меняющийся без
  анонса, — повод слать анонс сразу при изменении (`_syncGateway`), иначе
  соседи видят старое до следующего тика.
- [ ] Метка «шлюз» и список сетей показываются во всех местах, где виден узел:
  шапка, «Узлы», владелец в каталоге; своя карточка — не исключение.
- [ ] Сообщение и кнопка обновления выводятся из состояния updater, а не из
  отдельного флага: фаза `idle` прячет полосу целиком, поэтому каждая ветка
  `tick`/`_evaluateRestart`, которая оставляет версию «подготовленной» или
  «найденной у соседей», обязана ставить фазу с кнопкой «Обновить сейчас»
  (в обход канарейки). Пропавшее у клиента сообщение — сперва смотреть фазу и
  `canUpdateNow` в снимке.

## 8. Метрики и документация

- [ ] Новая сущность или состояние отражено в `metrics.js`; тест поймает
  метрику без описания в METRICS.md, но не отсутствие метрики.
- [ ] Изменены метрики → `npm run build:grafana` (JSON руками не править).
- [ ] README, PROTOCOL, HANDOVER, AGENTS.md не противоречат поведению
  («туннелей нет» и «только с ключом» жили в README месяц после кода).
- [ ] STATE.md обновлён тем же шагом; в публичные файлы не попали внутренние
  адреса и имена серверов.

## 9. Тесты

- [ ] Новая ветка кода — новый тест; гонка — тест с управляемым промисом
  (образец: release-race), а не sleep.
- [ ] Тест проверяет ветки и инварианты, а не «функция не упала».
- [ ] Тест не флейкует под нагрузкой: неготовое состояние — опрос с таймаутом
  (metrics), а не мгновенный assert.
- [ ] `npm test` целиком и `npm run check` перед коммитом; на Node 20 glob
  молча гонял ноль тестов — список в package.json явный, инвариант следит.

## 10. Стиль и процесс

- [ ] Комментарии — «почему», не «что»; нестандартное решение объяснено на
  месте принятия.
- [ ] Ноль зависимостей: `npm install` не появился; нужен модуль — сначала
  подумать, потом просить исключение.
- [ ] Один шаг — один коммит; сообщение на русском, без `Co-Authored-By`;
  `git add` только своих путей.
- [ ] Push — только по команде человека; теги версий — в оба репозитория.
- [ ] Публичный репозиторий: адреса, имена серверов и людей — не в файлы,
  не в сообщения коммитов, не в релизы.
