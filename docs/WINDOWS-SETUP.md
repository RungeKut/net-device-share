# Установка на Windows 10 x64

Приложение не создаёт устройства в «Диспетчере устройств» самостоятельно — это
делает драйвер уровня ядра, который должен быть подписан Microsoft. Написать
такой драйвер из прикладного кода нельзя ни на одном языке, поэтому Net Device Share
управляет готовыми реализациями USB/IP, а на себя берёт всё остальное:
обнаружение узлов, общий каталог, учёт занятости и интерфейс.

## Самый короткий путь: кнопка в приложении

Запустите `start.bat`. Если чего-то не хватает, в шапке появится сообщение
с кнопкой **«Установить»** — нажмите её и подтвердите запрос UAC.

Всё нужное уже лежит в папке `installers/` рядом с приложением, **интернет не
нужен**. Перед запуском файлы проверяются по SHA-256 и по подписи Authenticode;
установщики запускаются напрямую, поэтому запрос прав придёт на каждый
компонент — в окне UAC будет виден его издатель.
После неё приложение само перепроверяет окружение — перезапускать не требуется.

Разделы ниже нужны, если вы ставите компоненты вручную, разбираетесь с
неполадкой или настраиваете машину без графического интерфейса.

---

Две роли ставятся **независимо**. Нужна только раздача — ставьте только
usbipd-win. Нужно только подключать чужие устройства — только usbip-win2.

| Роль | Пакет | Что делает |
|---|---|---|
| раздача своих устройств | **usbipd-win** | отдаёт устройство драйверу-заглушке и слушает TCP 3240 |
| подключение чужих | **usbip-win2** | драйвер VHCI: устройство появляется в «Диспетчере устройств» |

Проверить, что получилось, в любой момент:

```
node src\main.js --doctor
```

---

## 1. Раздача своих устройств — usbipd-win

Поддерживается Windows 10 начиная с версии 1809 (сборка 17763), x64.

**Через winget** — если он есть:

```
winget install --interactive --exact dorssel.usbipd-win
```

На части машин с Windows 10 winget отсутствует: он поставляется в составе
«Установщика приложений» (App Installer), и в старых версиях пакета (примерно
до 1.11) команды `winget` ещё нет. Проверить: `winget --version`.

**Вручную** — способ, работающий всегда: скачайте `usbipd-win_<версия>_x64.msi`
со страницы <https://github.com/dorssel/usbipd-win/releases> и установите.
Тихая установка: `msiexec /i usbipd-win_<версия>_x64.msi /qn /norestart`.

Установщик регистрирует службу `usbipd` и сам добавляет правило брандмауэра
для TCP 3240. Проверка:

```
usbipd list
```

Команда должна вывести список устройств с колонками `BUSID`, `VID:PID`,
`DEVICE`, `STATE`.

> **Права администратора обязательны.** Операции `bind`/`unbind` выполняются
> только с повышенными правами. Запускайте Net Device Share от имени
> администратора, иначе публикация будет завершаться ошибкой
> «не удалось подготовить устройство».

## 2. Подключение чужих устройств — usbip-win2

Это драйвер VHCI. Именно он создаёт устройство в «Диспетчере устройств».

1. Скачайте установщик со страницы
   <https://github.com/vadimgrn/usbip-win2/releases> — файл `USBip-<версия>-x64.exe`
   (установщик Inno Setup, не MSI).
2. Установите. Утилита `usbip.exe` попадает в `C:\Program Files\USBip\`.
   Тихая установка: `USBip-<версия>-x64.exe /VERYSILENT /NORESTART /SP-`.
3. Проверьте: `usbip.exe port` — должен вывести пустой список портов, а не
   ошибку запуска.

### Нужен ли режим тестовой подписи

**Начиная с версии 0.9.8.0 — нет.** Драйверы в составе установщика подписаны
через attestation signing, и `pnputil /enum-drivers` показывает у них издателя
`Microsoft Windows Hardware Compatibility Publisher`. Windows 10 x64 (проверено
на сборке 19045) загружает их штатно: ни `bcdedit /set testsigning on`, ни
отключение Secure Boot, ни перезагрузка не требуются. Сразу после установки в
«Диспетчере устройств» появляется узел `USBip 3.X Emulated Host Controller`
в состоянии «OK».

Проверить, что драйвер действительно загрузился:

```
pnputil /enum-drivers | findstr /i usbip
```

Если в вашей сборке Windows драйвер всё же откажется загружаться (статус
устройства с ошибкой, код 52 — «не удаётся проверить цифровую подпись»),
режим тестовой подписи включается так, в командной строке **от администратора**:

```
bcdedit /set testsigning on
```

После перезагрузки в правом нижнем углу рабочего стола появится надпись
«Тестовый режим». Отключается обратно: `bcdedit /set testsigning off`.

> Это крайняя мера, а не штатный шаг. В тестовом режиме система загружает
> драйверы с самоподписанными сертификатами, а при включённом Secure Boot его
> придётся отключать в UEFI. Если это неприемлемо, компьютер всё равно может
> **раздавать** свои устройства: для этой роли нужен только usbipd-win.

> Отдельно стоит знать: установщик usbip-win2 подписан не автором проекта, а
> сторонней компанией (Cloudyne Systems / Scheibling Consulting AB). Подпись
> действительна, но при установке драйвера ядра это факт, который лучше
> проверить самостоятельно — `Get-AuthenticodeSignature` по скачанному файлу.

## 3. Брандмауэр

Нужны пять портов. Проще всего прилагаемым скриптом, **от администратора**:

```
powershell -ExecutionPolicy Bypass -File scripts\firewall-windows.ps1
```

Он создаёт правила для профилей «Домен» и «Частная сеть»:

| Порт | Протокол | Назначение |
|---|---|---|
| 47811 | UDP | обнаружение узлов |
| 47812 | TCP | каталог устройств и занятость |
| 3240 | TCP | данные USB/IP |
| 47813 | TCP | данные USB/IP через счётчик трафика |
| 47814 | TCP | кадры отданной сетевой карты |

> Правило для 3240 обычно создаёт установщик usbipd-win (правило называется
> `usbipd`). Скрипт это проверяет и своё правило заводит, только если чужого нет,
> — чтобы не плодить два правила на один порт.
>
> Проверять наличие правил нужно **из консоли администратора**:
> `Get-NetFirewallRule` без повышенных прав завершается ошибкой «Access is
> denied», а с `-ErrorAction SilentlyContinue` молча возвращает пустой список —
> и легко принять это за отсутствие правил. Надёжнее и без прав работает
> `netsh advfirewall firewall show rule name=all`.

Правила нужны на **каждом** компьютере сети, а не только на том, который
раздаёт устройства: обнаружение и каталог работают в обе стороны.

Удалить правила: `scripts\firewall-windows.ps1 -Remove`.
Если порт 3240 у вас уже открыт чем-то другим: `-SkipUsbip`.

> Правила намеренно не создаются для профиля «Общедоступная сеть». Раздавать USB
> в кафе или гостинице — не то, что стоит включать по умолчанию.

**Адаптеры приложения** — чужая карта, занятая этим компьютером,
виртуальные адаптеры коммутаторов и подключённые к коммутаторам TAP-адаптеры
других программ — Windows поначалу относит к
общедоступной сети, где входящие закрыты: приборы стенда не достучатся до
серверов, запущенных на этом компьютере. Приложение (с правами
администратора) переводит их сеть в «частную» само, как только Windows её
опознает. Если сетевым экраном служит сторонний продукт (например,
Kaspersky Endpoint Security — тогда брандмауэр Windows показывается
выключенным), вкладка «Сеть» об этом напишет; тип сети он обычно берёт у
Windows, а если нет — поставьте сети адаптера статус «Локальная сеть» в его
настройках («Сетевой экран → Сети»).

## 4. Запуск

Двойной клик по `start.bat` в корне проекта. Он проверит версию Node.js,
запросит повышение прав (без них не работает публикация устройств) и запустит
приложение — интерфейс откроется в браузере сам.

Параметры приложения можно передавать прямо ему:

```
start.bat --name "БУХГАЛТЕРИЯ-1" --network 192.168.1.0/24
start.bat --doctor
start.bat -noadmin
```

`-noadmin` — собственный ключ запускающего файла: не запрашивать повышение прав.
Годится, когда нужно просто посмотреть каталог сети.

Либо напрямую, без него:

```
node src\main.js --name "БУХГАЛТЕРИЯ-1" --network 192.168.1.0/24
```

> `start.bat` сохранён в кодировке **CP866** (кодировка консоли Windows) с
> переводами строк CRLF. Если будете его править — сохраните в той же кодировке,
> иначе cmd покажет вместо сообщений мусор. Причина в заголовке самого файла.

## Если что-то не работает

**Кнопка «Установить» не появилась, хотя чего-то не хватает.**
Значит приложение не нашло файлы установщиков. Проверьте, что папка
`installers/` лежит рядом с `src/` и в ней есть `manifest.json` и каталог
`windows/`. Переменная `NDS_INSTALLERS_DIR` позволяет указать другой каталог.

**Установка сообщает, что контрольная сумма не совпала.**
Файл повреждён при копировании или подменён. Скачайте заново по ссылке из
`manifest.json` (поле `sourceUrl`) и обновите там же `sha256` — приложение
намеренно отказывается запускать то, что не сходится с манифестом.

**В шапке горит «раздача» зачёркнутой.**
Не найден `usbipd.exe`. Проверьте `usbipd list` в новом окне консоли — после
установки нужно перезапустить консоль, чтобы обновился `PATH`. Путь можно задать
вручную: «Настройки» → «Пути к утилитам USB/IP».

**В шапке зачёркнуто «подключение».**
Не найден `usbip.exe` из usbip-win2. Тот же способ: проверьте `usbip.exe port`,
при необходимости укажите путь в настройках.

**«Не удалось подготовить устройство» при занятии.**
Почти всегда — запуск без прав администратора. Реже устройство удерживается
своим драйвером; приложение в этом случае само пробует `usbipd bind --force`.

**Узлы не видят друг друга.**
1. `node src\main.js --networks` на обоих компьютерах — подсеть должна совпадать.
   Если выбран виртуальный адаптер Hyper-V или WSL, задайте нужную явно:
   `--network 192.168.1.0/24`.
2. Проверьте правила брандмауэра (раздел 3) на **обоих** компьютерах.
3. Общий ключ должен совпадать. Узлы с разными ключами не видят друг друга — это
   штатное поведение.
4. Если сеть режет multicast, приложение всё равно достучится broadcast-ом, но
   только внутри одной подсети: через маршрутизатор такие пакеты не пройдут.

**Устройство занято, но в «Диспетчере устройств» не появилось.**
Посмотрите вкладку «Подключено ко мне»: там состояние подключения и номер порта
VHCI. Пустой порт VHCI обычно означает, что драйвер не загрузился. Проверьте
состояние узла `USBip 3.X Emulated Host Controller` в «Диспетчере устройств»:
если там ошибка с кодом 52, понадобится режим тестовой подписи (раздел 2).

**Устройство осталось занятым после аварии клиента.**
Это временно: аренда истечёт (по умолчанию через 30 с) и владелец освободит
устройство сам. Досрочно — кнопка «Отобрать» на компьютере владельца.
