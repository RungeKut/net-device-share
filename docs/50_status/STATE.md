# Состояние (точка возобновления)

Обновлено: 2026-10-23

> Снимок, ≤ 6 КБ. История — в git, подробности — в docs/HANDOVER.md.

## Цель

Приложение (версия считается из git: тег vX.Y + число коммитов) работает в сети; шлюзы между сетями, туннели и общий мост — в master.

## Сделано

- Шлюз: метка «🌉 шлюз» у самого узла (шапка, «Узлы», владелец в каталоге — у записи «себя» не было `nets`) и у соседей во вкладке «Узлы». Автовыбор сетей берёт и адреса не из частных диапазонов (кроме 169.254), основной — частная: прямой кабель на 200.100.1.0/24 раньше оставлял узел в одной сети. Шлюз никто не назначает: узел с `nets > 1` сам пересказывает каталог (README, «Кто шлюз»).
- Обновление: обратный отсчёт («подтверждение через 45 с», «перезапуск через N с», очередь) считает окно по меткам `trialUntil`/`graceUntil`/`eligibleAt`, тик раз в секунду меняет только текст (полоса не перерисовывается — иначе терялся клик по «Обновить сейчас»). Пропажу сообщения у клиента по коду не воспроизвёл — нужны режим, фаза, лог с узла.
- Скорость моста у соседей больше не замерзает: `PeerRegistry._refreshBusy` считает занятым узел, у чьих карт есть `joins` (у карты в мосту `claim` нет, и опрос раз в 5 с её пропускал). Тест в `test/net-traffic.test.mjs` гоняется для занятия и для моста. На живых узлах не проверено — им надо обновиться.
- Автозапуск службой: задание `NetDeviceShare` от SYSTEM (S-1-5-18), триггеры — загрузка (+30 с) и вход любого пользователя; приложение стартует и у пользователей без админ-прав. Создаётся только если каталог не открыт на запись обычным пользователям (проверка ACL), иначе прежний S4U от пользователя. `autostart.home` передаёт каталог настроек SYSTEM для неустановленной копии. Установщик: пункт «как службу», сразу `schtasks /Run` (без UAC); без автозапуска последний шаг — `runascurrentuser` + `open.vbs /elevated`. `open.vbs` сперва просит задание, runas — только если задания нет (test/autostart.test.mjs).
- Статическое закрепление соседей моста: владелец передаёт держателю пары IP→MAC из сканера (`neighbors` в совете подключения), держатель закрепляет их Permanent на своём адаптере — гонка «кто быстрее ответил на ARP» за спорный адрес (машина рабочей сети с тем же IP, что у прибора) больше не отбирает трафик. Перепин при смене адреса.
- Очистка кэша соседей (ARP) расширена: при подключении чужой карты стираются записи подключаемой подсети **на всех адаптерах**, не только на взятом (маска рабочей сети бывает шире — адрес прибора существует и в офисной сети; застрявший там сосед уводил трафик мимо более узкого маршрута). `ipInPrefix` покрыта тестом (ip-prefix).
- Очистка кэша соседей (ARP) подключаемого адаптера при переносе IP и при смене адреса держателем (`flushNeighborCache`): после замены прибора Windows иначе помнит старый MAC до получаса. Причина ввода — живой случай P-стенда: конфликт IP 10.0.6.134 (прибор + Windows-машина) маскировался под «мост не работает».
- Чек-лист код-ревью `docs/REVIEW.md`: дерево из 11 веток с «почему» и живыми примерами грабель проекта; правило пополнения (новая грабля — листик, нет ветки — новая ветка, «прочее» запрещено).
- Метрики актуализированы под мост: держатели из joins видны в `nds_holder_*` и `nds_node_holders`, новые семейства `nds_device_join_info/_age_seconds/_join_traffic_*`; в дашборде Grafana панели «Личный трафик держателей общего моста» и «Узлов в общих мостах»; METRICS.md описывает новое.
- Скорость каждого держателя моста: личные счётчики по портам коммутатора (`netShare.holderMeters`), `statsFor(deviceId, holderId)`; в каталоге у карты «в мосту: А · 1,2 МБ/мин, …», держателю по heartbeat идёт его личная скорость, а не общая по карте.
- Диалог адреса при подключении в общий мост: после занятия карты в сети со статикой всплывает «Задать адрес адаптеру?» — предложенный адрес в поле (можно поправить), «Да, задать» / «Нет»; применение через существующий `/api/v1/net/held/ip`. В DHCP-сетях и при уже настроенном адаптере окно не появляется.
- Шлюз между сетями, туннели TCP, обнаружение на всех интерфейсах, открытый круг между подсетями (осознанное решение: граница — достижимость порта; приватность — ключ + снять обе галочки), общий мост, reaper TAP-адаптеров, подпись RPC v2, версия из git-тега.
- Правки по повторному код-ревью (2026-10-22): сбой опроса портов/сетей больше не «устройств нет» (hub), сбой списка адаптеров не «адаптер удалён» (waitTaps), занятость updater до первого await, срок у «Обновить сейчас», сериализация `_syncLegs`, один слушатель на туннель, валидация портов туннеля, чистка `tunnelCache`, мост-«иждивенец» дочищивается по netLent, адрес-совет не повторяется двум держателям; metrics-тест не падает на неготовом `/metrics`.
- Инфраструктура: `npm test` перечисляет файлы явно (glob на Node 20 молча гонял 0 тестов) + инвариант полноты в `check-files` (76 инвариантов); CI GitHub Actions (windows-latest: check + тесты); `.logs/` в .gitignore.
- Документация синхронизирована с кодом: README (выбор сети, сегменты, узлы без ключа, безопасность, состав), PROTOCOL (убрана «версия 2.3», задвоенный заголовок), HANDOVER, AGENTS.md.
