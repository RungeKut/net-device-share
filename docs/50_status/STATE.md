# Состояние (точка возобновления)

Обновлено: 2026-11-01

> Снимок, ≤ 6 КБ. История — в git, подробности — в docs/HANDOVER.md.

## Цель

Приложение (версия из git: тег vX.Y + число коммитов) работает в сети; шлюзы между сетями, туннели и общий мост — в master.

## Сделано

- Узел за NAT (ВМ за Proxifier/x-ray, найдена живьём): отражение — чужой nodeId с нашего адреса и порта — не заводится в список, видно в настройках, уходит с обменом той ВМ (полоса с рецептом, пока утечка UDP не закрыта). Отражение не пересказывается и не принимается с нашего адреса; «чужая сеть» — источник вне объявленной сети; ключ маршрута — адрес:порт|via. «Выйти» скрыта на localhost. Рецепт — WINDOWS-SETUP.
- Повторное ревью правок: «призрак» на анонсе — без os.networkInterfaces() в горячем пути, без краха на кривом nodeId; после BYE — сразу офлайн.
- По итогам ревью: BYE при живом пересказе шлюза переводит запись на relay; снимок — `_peerView` без внутренностей реестра; `_syncGateway` по составу живых сетей, не по числу; тест метрик — случайный discovery-порт.
- Ревью обнаружения (полный проход + стенд). «Сеть → авто» корректен (шлюз за ~5 с). Нога с живым broadcast и молчащим multicast вечно «ломалась» — ремонт глушил сеть; нога здорова при одном рабочем канале. Слышимость по сетям (lastHeardAt), подсказка исключённых карт, схема docs/img/discovery-flow.svg.
- Стенд `scripts/loadtest.mjs` (таймеры ±15%), замер — `docs/LOADTEST.md`: 200 узлов сошлись, 400 — нет (лавина TCP-запросов состояния; гипотеза), soak чист.
- Ревью «не видят друг друга»: QUERY отвечает всегда, самолечение UDP, счётчики отброшенного, клон `nodeId`, круг не скачет, кэш туннелей сбрасывается, 401 различает часы и ключ, битый конфиг — копия.
- Опрос COM/LPT/сетей: один PowerShell вместо двух, только при изменении (`DeviceHub._listSlow`); 20 узлов: 57% CPU → ~5%.
- Шлюз: метка «🌉 шлюз» у узла и соседей; автовыбор сетей берёт и не частные адреса (кроме 169.254). Звание по живым соседям минимум в двух сетях (`PeerRegistry.liveNetworks`), пропал сосед — уходит сразу.
- Автозапуск службой от SYSTEM; статический ARP соседям моста; очистка ARP; диалог адреса в мост.
- Раньше: шлюз, туннели TCP, открытый круг, общий мост, отсчёт обновления и скорость моста у соседей, подпись RPC v2, версия из git-тега, `docs/REVIEW.md`, CI.

## Открытые вопросы

- Не проверено (HANDOVER, 7): автозапуск от SYSTEM; Linux-бэкенд; байты живого USB; самообновление между компьютерами; «Копировать драйвер»; перенос IP карты.
- Автовыбор берёт и карту, смотрящую к провайдеру (непубличный адрес): узел объявится и туда. Принято осознанно, задать сеть можно вручную.
- Открытый круг без ключа принимает любые вызовы — так задумано (README, «Узлы без ключа»). Проброс COM идёт через com0com (нужна тестовая подпись, как у драйверов проекта); LPT — только бронь. Живой COM на стенде с настоящим прибором не проверен.
