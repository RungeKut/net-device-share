# Экономия токенов

Стоимость каждого вызова инструмента пропорциональна размеру контекста:
сессия 800К в ~8 раз дороже той же работы на 100К. Кэш верхнего агента
живёт ~1 час, субагента — ~5 минут; промах кэша на большом контексте =
платить за каждый токен заново.

1. Контекст держать ниже ~200К; дробить на шаги, каждый шаг = коммит +
   обновление STATE.md.
2. Корневой инструкционный файл (AGENTS.md/CLAUDE.md) ≤ 2 КБ — его читает
   каждый субагент.
3. Не читать файл целиком: Grep с `-n`, затем Read с offset/limit;
   прочитанное не перечитывать.
4. Большой вывод (сборка, лог) — в файл scratchpad, в контекст только
   `tail` / `grep`.
5. Дешёвые модели на механику, дорогие на архитектуру и ревью.
6. Ответ субагента ≤ 15 строк, остальное — в файлы.
7. Не будить спящего субагента ради мелочи.
8. Задачи агентам пачками, заранее нарезанными, чтобы контекст исполнителя
   ≤ ~150К.
9. Долгие операции в фон, без поллинга; кэш не греть пустыми вызовами.
10. Комментарии в коде запрещены — они превращаются во вторую кодовую базу
    и тратят токены на каждом чтении.
11. Документы — справочник; файл в docs/ ≤ 6 КБ, иначе делить.
12. Не копировать содержимое файлов в файлы — только ссылка на путь.

Квота Kimi Code (403 «usage limit», 429) — скилл `quota-resume`: точное
время сброса, один будильник, без слепых ретраев.
