# Компактизация контекста

`/compact` не теряет работу, если вся она лежит в файлах. Сжимать самому и
рано — дешевле, чем ждать автокомпакта на пределе.

## Безопасный момент (все 4 условия)

1. git чист (шаг закоммичен);
2. STATE.md содержит цель/сделанное/следующий шаг/открытые вопросы/id субагентов;
3. нет незаписанных решений;
4. результаты субагентов сохранены в файлы.

## Хорошие точки

- переход проектирование → реализация;
- после модуля с зелёной сборкой;
- после ревью;
- контекст > 200К или «вязкость» (повторные вопросы, путаница в именах).

## Плохие точки

- посреди отладки с гипотезами в голове (сначала раздел «Гипотезы» в STATE.md);
- пока вывод сборки/тестов не прочитан;
- пока решение не зафиксировано в документе.

## Порядок

1. Обновить STATE.md → коммит.
2. Сообщить: «контекст N К, можно сжать, точка возобновления — STATE.md».
3. Compact с подсказкой: «сохранить цель шага, пути изменённых файлов,
   открытые вопросы; вывод инструментов отбросить».
4. После компакта читать только корневой AGENTS.md и STATE.md.

Субагентов не сжимать, а закрывать. Компакт верхнего агента допустим в любой
момент, пока субагенты работают — по факту завершения они отчитаются как
обычно.
