# Установщики

Всё, что нужно приложению, лежит здесь и ставится **само при первом запуске**.
Интернет для этого не требуется: так машину можно поднять в цеху, в
изолированном сегменте сети или на стенде без выхода наружу.

| Файл | Роль | Версия | Размер | Лицензия |
|---|---|---|---|---|
| `windows/node-v24.21.0-x64.msi` | среда выполнения | 24.21.0 | 31.7 МБ | MIT |
| `windows/usbipd-win_5.3.0_x64.msi` | раздача своих устройств | 5.3.0 | 4.3 МБ | GPL-3.0 |
| `windows/USBip-0.9.8.0-x64.exe` | подключение чужих устройств | 0.9.8.0 | 25.2 МБ | GPL-3.0 |

`manifest.json` — описание для приложения: контрольные суммы, ожидаемые
подписанты, команды тихой установки и пути, по которым проверяется результат.
Приложение читает именно его, а не гадает по именам файлов.

> **Node.js в комплекте дважды.** Рядом с `start.bat` лежит `node.exe` — на
> нём комплект работает без установки чего бы то ни было. Установщик из этого
> каталога ставит Node **в систему**, и нужен он только тем, кто разворачивает
> приложение из исходников. Если Node в системе уже есть, установщик не
> запускается.

---

## Как это работает

При запуске приложение смотрит, чего не хватает, и доустанавливает:

1. Сверяет **SHA-256** каждого файла с манифестом. Не совпало — установка
   отменяется целиком.
2. Проверяет **подпись Authenticode**. Статус не `Valid` — установка отменяется.
3. Запускает установщики **напрямую, по очереди**, с повышением прав.
   Запрос UAC приходит на каждый компонент, зато в окне виден издатель
   настоящего установщика, а не посредник. Временные сценарии не создаются
   и политика исполнения PowerShell не обходится — иначе приложение было бы
   неотличимо от загрузчика вредоносного кода и попадало бы под эвристику
   антивирусов.
4. После установки перепроверяет окружение и обновляет интерфейс.

Проверки не косметические: это установщик драйвера уровня ядра, запускаемый
с правами администратора. На слово файлу рядом с приложением верить нельзя —
папку мог подменить кто угодно с доступом к диску.

Уже установленное не трогается. Отключается всё это галочкой
**«Ставить недостающее при запуске»** в настройках; тогда остаётся кнопка
«Установить» рядом с сообщением о неполном окружении.

## Происхождение файлов и как это проверить

| | Node.js | usbipd-win | usbip-win2 |
|---|---|---|---|
| проект | <https://github.com/nodejs/node> | <https://github.com/dorssel/usbipd-win> | <https://github.com/vadimgrn/usbip-win2> |
| лицензия | MIT | GPL-3.0 | GPL-3.0 |
| подписант | OpenJS Foundation | Open Source Developer, Frans van Dorsselaer | Cloudyne Systems (Scheibling Consulting AB) |

Точные адреса, откуда файлы взяты, записаны в `manifest.json` в поле
`sourceUrl`. Проверить самостоятельно:

```powershell
Get-FileHash .\windows\node-v24.21.0-x64.msi -Algorithm SHA256
Get-AuthenticodeSignature .\windows\USBip-0.9.8.0-x64.exe | Format-List Status, SignerCertificate
```

Ожидаемые суммы:

```
bb0eaee134f9357f22aea915ee793343e627aefc1e66488164bac6915bce2cac  node-v24.21.0-x64.msi
1c984914aec944de19b64eff232421439629699f8138e3ddc29301175bc6d938  usbipd-win_5.3.0_x64.msi
81f426741f7ee2ed991febe24a22daca8400b6ae2f171054e3fb404897e15d39  USBip-0.9.8.0-x64.exe
```

Сумму Node.js можно сверить с первоисточником —
<https://nodejs.org/dist/v24.21.0/SHASUMS256.txt>.

> **Обратите внимание.** Установщик usbip-win2 подписан не автором проекта,
> а сторонней компанией. Подпись действительна, но при установке драйвера ядра
> это стоит понимать осознанно. Если политика вашей организации это запрещает,
> удалите файл и уберите его из `manifest.json`: приложение сохранит роль
> сервера (раздачу своих устройств).

## Исходные тексты (GPL-3.0)

usbipd-win и usbip-win2 распространяются под GPL-3.0. Вместе с двоичными
файлами полагается предоставлять соответствующие исходные тексты — здесь это
сделано указанием на то же место, откуда взяты сами сборки:

| Компонент | Исходные тексты этой версии |
|---|---|
| usbipd-win 5.3.0 | <https://github.com/dorssel/usbipd-win/tree/v5.3.0> |
| usbip-win2 0.9.8.0 | <https://github.com/vadimgrn/usbip-win2/tree/v.0.9.8.0> |

Эти же адреса продублированы в `manifest.json` (`project` и `sourceUrl`).
Если исходные тексты понадобятся, а указанные страницы окажутся недоступны,
напишите владельцу репозитория — копия будет предоставлена.

Сами файлы никак не изменены: это ровно те сборки, которые опубликовали
авторы, что подтверждается их подписями и контрольными суммами.

## Обновление версий

1. Скачайте новые файлы со страниц релизов и положите в `windows/`:

   ```
   node scripts/fetch-installers.mjs
   ```

   Скрипт берёт адреса из `manifest.json` и сверяет SHA-256 — подменить файл
   по дороге не выйдет.
2. Если версия сменилась, впишите в `manifest.json` новые имя файла, версию,
   `sourceUrl` и сумму (`Get-FileHash -Algorithm SHA256`), а в этот файл —
   адрес исходных текстов новой версии.
3. Проверьте `verifyPaths`: если установщик сменил каталог, приложение иначе
   не увидит результат и сочтёт установку неудавшейся.
4. Старые файлы удалите — приложение берёт ровно то, что указано в манифесте.
5. Прогоните `npm run check`: суммы из манифеста сверяются с файлами.

Каталог можно вынести за пределы проекта переменной `NDS_INSTALLERS_DIR` —
это нужно при сборке дистрибутива, где установщики лежат отдельно от кода.

## Установка вручную

Если что-то пошло не так, то же самое делается из консоли
**от администратора**:

```
msiexec /i windows\node-v24.21.0-x64.msi /qn /norestart
msiexec /i windows\usbipd-win_5.3.0_x64.msi /qn /norestart
windows\USBip-0.9.8.0-x64.exe /VERYSILENT /NORESTART /SP-
```

Проверка результата: `node src\main.js --doctor` в корне проекта.

## Linux

Вложенных файлов для Linux нет и не планируется: там USB/IP входит в ядро,
а утилиты ставятся штатным пакетным менеджером.

```
sudo apt install linux-tools-generic usbip     # Debian/Ubuntu
sudo dnf install usbip                         # Fedora
sudo modprobe usbip_host vhci_hcd
```

Проще запустить `scripts/run-linux.sh` — он загрузит модули сам.
